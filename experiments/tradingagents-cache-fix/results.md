## Control: does tracing change what we measure?

The patched and baseline arms are both traced, so instrumentation cancels in the comparison — but only if it is not doing something dramatic. Untraced runs (baseline code, no OpenTelemetry, usage read passively from response bodies) test that directly:

- traced baseline runs: 9.7%, 4.6%, 8.3% (mean 7.5%)
- untraced control runs, same config as run 01: 8.6%, 3.4% (mean 6.0%)
- patched runs, for scale: 28.4%, 34.1%, 34.6% (mean 32.4%)

Traced baselines span 4.6% to 9.7%; 1 of 2 untraced rates fall inside that range. The traced-vs-untraced difference of means is 1.5 points — smaller than the baseline arm's own run-to-run spread (5.1 points across configs, and 9.3% vs 18.1% on two captures of the same config a week apart), and an order of magnitude smaller than the patch's effect (+24.9 points). No untraced run comes within 20 points of the worst patched run.

So: nothing here suggests instrumentation manufactured the result, and with n=2 controls this is a consistency check, not a proof of exact neutrality.
