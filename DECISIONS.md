# Decision log

Short, dated notes on the non-obvious calls, so the "why" survives longer than my memory of it.

## 001 — Verdicts come from deterministic rules, not an LLM (2026-08-29)

**Decision:** the diagnosis engine is a library of explicit, testable rules. No model call anywhere in the verdict path. If an LLM is ever used, it drafts prose or patch text from an already-decided finding, in a module the detectors cannot import.

**Why:** same trace in, same findings out; every detector can be unit-tested against labeled fixtures and given a measured precision; running the tool is free, which matters for a tool whose whole point is reducing cost; and every finding carries an evidence pointer instead of a vibe.

**Cost accepted:** rules only catch what I have enumerated. An enumerated catalog with measured precision beats open-ended guesses I can't test.

## 002 — Name: tokenaudit, not cachelens (2026-08-29)

The working name for this project was "cachelens". The day-one collision check found [cachelens on PyPI](https://pypi.org/project/cachelens/) — released June 2026, an SDK-wrapper cache meter, i.e. a neighbor in this space, not just a name squatter. Shipping a lookalike name would be unfair to them and confusing for everyone.

Picked **tokenaudit** over the other candidates (wastelens, cachedoctor) for two reasons: it leaves the cache-/-lens naming family entirely, and several planned detectors (retry storms, context bloat, tool-schema bloat) are token-waste problems that aren't cache problems at all, so "cache" in the name undersold the scope. Verified free on PyPI and GitHub 2026-08-29.

## 003 — Apache-2.0, not MIT (2026-08-29)

Explicit patent grant, and it matches the ecosystem this project sits in (OpenTelemetry is Apache-2.0).

## 004 — src layout and strict mypy from the first commit (2026-08-29)

src/ layout so tests import the installed package rather than the working directory. `mypy --strict` costs nothing to adopt on an empty package and a lot to adopt later; the detector engine will be pure functions, which is exactly the code strict typing is cheap for.

## 005 — The rulebook is JSON inside the package, not YAML beside it (2026-08-30)

**Decision:** provider caching constants live in `src/tokenaudit/rulebook/*.json`, loaded with the standard library via `importlib.resources`, and ship inside the wheel.

**Why:** the package has zero runtime dependencies, and adding a YAML parser just to read our own constants would end that for no gain — sources and notes are data fields, so YAML's comments aren't needed. Packaging the data means the installed CLI works without a repo checkout. Two boundaries drawn at the same time: trace field-name *mappings* stay in `ingest/dialects.py` (one owner, no code/data drift), and prices appear only where verified — unknown numbers are `null` with a note, never a guess. The corpus generator now reads these same files, so the simulator and the detectors share one set of constants, with the byte-exact corpus regeneration test guarding every edit.

## 006 — argparse over Typer; a ratio over a weighted score; records over probabilities (2026-08-30)

Three calls made together for the 0.1.0 release, all in service of the same principle.

**CLI stays argparse.** Typer gives nicer help text at the cost of the package's zero-runtime-dependency property — a bad trade for a tool whose pitch includes "installs nothing else and never phones home".

**The cache health score is `realized / achievable` savings** — realized cache savings over realized-plus-what-the-findings-quantify. Both halves are computed the same way, so there are no weights to defend; overlapping findings make the denominator conservative, so the score is presented as a floor and says so.

**Findings carry a corpus record, not a confidence number.** A precision float computed from a 16-fixture corpus would be theater. The package ships the raw record instead — "3/4 planted cases found, 0 false alarms in N negatives" — generated by the eval harness and drift-tested, so what appears next to a finding is exactly what was measured.

## 007 — Line-level digests, and detectors that look across sessions (2026-11-12)

**Decision:** ingest keeps a truncated SHA-256 and length for every line of every message, in memory only, next to the existing whole-message digest. Two detectors use them: `misordered_shared_context` within a session and `cross_session_drift` across sessions.

**Why:** the TradingAgents diagnosis was done by hand, because whole-message hashes can't see the same reports inside two different messages. The tool called those runs clean while the case study showed a 4x improvement. Lines are fine enough to find shared content and to pin a date to one line, and coarse enough to stay fast.

**Boundaries:** line digests never leave the process (`tokenaudit ingest` drops them), because a hash of a short line is easy to guess. Cross-session findings count toward a CI gate's findings but not toward the health floor, since whether sessions share a cache depends on when they ran; the low impact bound only counts sessions that started within the model's cache lifetime of each other. Each new detector defers to an existing one where they overlap: a short edit near the start of a prompt is prefix drift, and a value that changes on every call within a session is prefix drift too.

## 008 — Price against the fix, per model; new detectors yield to older ones (2026-11-12)

**Decision:** a finding's impact is what the affected tokens cost minus what they would have cost under the fix, using the model's read and write multipliers from the rulebook. A request that wrote the cache is charged the write premium, not full price. Dollars appear only when the rulebook has a verified input price; tiered prices (Haiku 5.5) stay in tokens.

**Why:** a flat discount overstated waste on models with cheaper reads and ignored that a miss on Anthropic often costs more than a plain request, because it writes the cache. Keeping the rates in one module means a rulebook update reprices every detector at once.

**Boundaries:** `tool_schema_bloat` prints tool names, which are identifiers a developer chose rather than prompt text. It counts a tool as used if any request with the same tool set called it, so a shared registry where every tool is used by some agent is not flagged; telling agents apart needs more than a trace carries. `missing_cache_markers` only counts block-aligned prefixes repeated within the cache lifetime, since a breakpoint sits at a block's end and a later repeat would have missed anyway. It leaves growing conversations to `context_bloat` and byte-identical re-sends to `retry_storm`, whose fixes fit those cases better.
