## anthropic

TTL semantics: **from_request_start** · accounting: **exclusive** · verified 2026-08-29 · [source](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

Minimum cacheable prompt length is model-tiered and does not track model size. The system may add one automatic top-level breakpoint, which consumes one of the four explicit slots. A breakpoint checks at most 20 positions, counting itself as the first. TTL runs from the START of the request that wrote or last read the entry. Raw SDK usage fields are exclusive: total input = input_tokens + cache_read_input_tokens + cache_creation_input_tokens.

## google

TTL semantics: **?** · accounting: **nested** · verified 2026-08-29 · [source](https://ai.google.dev/gemini-api/docs/caching)

The Interactions API supports implicit caching only; explicit cache objects are not supported there, so 'you never created a cache' is not a valid finding on that path. Cached tokens surface as usage.total_cached_tokens. TTL and discount rate are not published alongside the minimums; they are recorded as unknown rather than guessed.

## openai

TTL semantics: **sliding_from_last_use** · accounting: **nested** · verified 2026-08-29 · [source](https://developers.openai.com/api/docs/guides/prompt-caching)

Caching is automatic (prefix-based). Invalidated by model changes; tool definition, schema or ORDERING changes; and parameter flips (reasoning.effort, text.verbosity, text.format). prompt_cache_key influences routing so matching prefixes land on the machine holding the cache. Usage fields are nested: input_tokens_details.cached_tokens sits INSIDE the input total, and there is no separately billed cache-write count in usage (cache writes bill at 1.25x within input).
